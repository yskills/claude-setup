# Local worker next to Claude (plan rewritten on verified claims, 2026-10-07)

**Easy answer.** Nothing "trains itself". Day 1, no training: one Qwen served on the PC with llama.cpp, three role files (scout, story, research), every job logged as a trace; Claude checks the output, passing traces become the examples and playbook lines the worker gets next time. That is what Odysseus, Hermes and OpenClaw actually do at run time. Weight training is step 2, triggered by data, one Unsloth LoRA on Qwen3.5-9B, shipped only if it beats the prompt+examples setup on a sealed holdout. Don't wait for Ajax: no weights, no date ("when it's ready"), and its repo has SFT data and eval scripts but no trainer. yskills does: paste `nvidia-smi` + RAM size, ok a ~20 GB download, thumbs on ~5 outputs a week, ok any GPU rental, read the legal verdict.

## Setup
| VRAM | Worker (GGUF Q4_K_M via `llama-server --jinja`, `-c` as big as fits) | Trainee (Unsloth bf16 LoRA) |
|---|---|---|
| 12-16 GB | Qwen3.6-35B-A3B with `--cpu-moe` (38.8 tok/s on a 4070, short context; **unconfirmed**: ~32 GB system RAM needed, settled by yskills' RAM size) or Gemma 4 12B QAT | Qwen3.5-4B local (10 GB); 9B on a rented 24-32 GB card ($0.34-0.69/h RTX 4090, ~$1-3 per run, estimate) |
| 24 GB | Qwen3.8-27B, Apache 2.0, ~17 GB file, ~18 GB VRAM at 8k context, 41 tok/s on a 3090 at tg128 (drops to ~29 at 32k on a 5090) | Qwen3.5-9B local: 22 GB minimum, seq 2-4k, batch 1-2, grad checkpointing, ~2 GB spare; no QLoRA on Qwen3.5 |

- Repo `yskills/worker` (TS CLI, Python only in `train/`): `roles/<role>/ROLE.md` (<=60 lines), `examples/` (cap 30, our choice, no source), `playbook.md` (delta edits), `memory/<role>.md`, `jobs/inbox/`, `traces/YYYY-MM/*.jsonl`, `eval/<role>/holdout/` (sealed 20-25%, split by task). Research role gets its own search API; Claude's WebSearch does not travel.
- Gate: worker- or teacher-proposed skills and playbook lines are `draft` and stay out of the worker's prompt until Claude or a test promotes them. Odysseus shows an approval card but still injects drafts on the next turn; we don't.
- Claude Code: main session stays on Anthropic. Claude runs `npx worker run <role> jobs/inbox/<id>.json` from Bash, checks the output, writes the verdict into the trace. Cloud threads drop job files, the PC session picks them up; no tunnel. Optional second profile at 24 GB: `CLAUDE_CONFIG_DIR=%USERPROFILE%\.claude-local`, `ANTHROPIC_BASE_URL=http://127.0.0.1:8080`, `ANTHROPIC_AUTH_TOKEN=x` (not `ANTHROPIC_API_KEY`: background calls would then ask the local server for a Haiku ID), all `ANTHROPIC_DEFAULT_*_MODEL` + `CLAUDE_CODE_SUBAGENT_MODEL` = local tag, `CLAUDE_CODE_MAX_CONTEXT_TOKENS=64000` (values under 100k untested); `CLAUDE_CODE_ATTRIBUTION_HEADER=0` is optional from v2.1.181. Anthropic calls routing to non-Claude models unsupported. Mixed Claude + local subagents in one session needs a router; skipped.
- Fast loop: checker per role, in code where possible (scout = JSON schema + link resolves + licence field; research = two citations resolve; story = yskills thumbs + blind pairwise vs current best, after a 1-hour German bake-off Qwen vs Gemma 4). Pass -> candidate example, Claude promotes (dedupe, cap 30) and adds one playbook bullet. Fail -> classify route / contract / tool / answer / model-owned; only model-owned failures count toward retraining. Monthly, inside the memory check: prune, rerun holdout, score into HQ.
- Slow loop, trigger not calendar: one role with 300+ checked traces, 60+ sealed, prompt+examples flat for two monthly checks. Scout first. Unsloth bf16 LoRA on Qwen3.5-9B, r=16, lr 1e-4 to 2e-4, 1-2 epochs, assistant-only loss, ~10% general + German replay, pinned versions, retrain from base each time. Merge, export GGUF Q4_K_M, confirm the merged file answers differently from base (Odysseus' vLLM LoRA was silently inactive: identical outputs on 177 cases), eval at temp 0 on the holdout, paired test, ship only above noise (~8 pts at n=60). Expect +3-8 pts on scout over a good prompt; dev scores overstate by ~5 pts.
- Training data: only the worker's own checker-passed outputs plus yskills' original text. No Claude text in any set, and Claude-judge labels used to pick rows are gray: Anthropic's support article (2026-03-16) lists "models for open-ended text generation" and "Outputs as training targets" as prohibited, which hits the story role hardest; Pro/Max accounts fall under the Consumer Terms. The `legal` skill checks the right terms and asks Anthropic in writing before any gray row is used.
