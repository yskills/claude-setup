# Keys for a shop

## Where keys live

Deploys run through Cloudflare Workers Builds (`publish` skill), so no shop key ever touches
GitHub.

1. **Worker secrets, Production.** Worker → Settings → Variables and secrets. The live site
   reads them from `env`. yskills pastes them there.
   - Never in `wrangler.jsonc` `vars`.
   - Never `NUXT_PUBLIC_*`: those ship to the browser.
2. **Worker secrets, Previews Base.** Only what previews need: a Stripe **sandbox** key and the
   preview's own `BETTER_AUTH_SECRET`. Never a production value. A Base secret reaches only
   previews created after it, so set them before the first PR.
3. **Local development.** `.dev.vars` (gitignored) holds test keys. `.dev.vars.example` lists
   the names.
4. **Stripe uses a restricted key** (`rk_test_…`, `rk_live_…`), not the full secret key.
   Stripe no longer recommends secret keys for new integrations.
5. **Keys never go into chat, an issue, a commit or a screenshot.** yskills pastes them into
   Cloudflare themselves.
6. **Cloud threads can't reach the Stripe or Cloudflare APIs**, and the build holds no shop
   keys. So the Stripe webhook endpoint is made once per mode by yskills (below), and
   `BETTER_AUTH_SECRET` is generated by `deploy.mjs` inside the build.
7. **Before the live key goes in:** Worker → Settings → Build → turn off non-production branch
   builds (`publish` skill: branch builds run with the deploy token).

## The keys

Use these secret names exactly; the Worker expects them. Cloudflare itself needs no key from
yskills beyond the one-time import in the `publish` skill.

| Secret | For | Create it | Test / live |
|---|---|---|---|
| `STRIPE_SECRET_KEY` | Checkout and refunds | [Stripe: API keys](https://dashboard.stripe.com/apikeys) → Create restricted key. Permissions: Checkout Sessions **Write** only (subscriptions: see `stripe-workers.md`). Add more only when a call fails with a permission error. Guide: [restricted keys](https://docs.stripe.com/keys/restricted-api-keys) | Test key from a sandbox now; live key at go-live. A live key is shown only once |
| `STRIPE_WEBHOOK_SECRET` | Verifying webhooks | [Stripe: Webhooks](https://dashboard.stripe.com/webhooks) → Add destination → Your account → events from `stripe-workers.md` (`WEBHOOK_EVENTS`) → URL `https://<live domain>/api/stripe/webhook`, API version = the SDK's `Stripe.API_VERSION`. Copy its signing secret (`whsec_…`) | One endpoint per mode: sandbox now, live at go-live. Previews skip the webhook: the return page records the payment |
| `SENDCLOUD_PUBLIC_KEY`, `SENDCLOUD_SECRET_KEY` | Creating parcels | [Sendcloud: create API keys](https://sendcloud.dev/docs/getting-started/how-to-create-your-api-keys) (steps in the Sendcloud panel) | Sendcloud has no test mode: parcels are only charged once you create a label |
| `RESEND_API_KEY` | Order confirmation emails | [Resend: API keys](https://resend.com/api-keys). Also verify the sending domain; Claude adds the DNS records in Cloudflare | One key, "sending access" only |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google login, if the shop has accounts | [Google Auth Platform → Clients](https://console.cloud.google.com/auth/clients), after the first deploy (Google needs the live URL) | One client |

`BETTER_AUTH_SECRET`, if the app has logins, is generated by `deploy.mjs` for production. For
Previews Base, yskills pastes any long random string (a password manager's generator).

**One Stripe key per mode.** The Worker needs only Checkout Sessions Write (plus what
subscriptions need, `stripe-workers.md`); nobody creates webhooks by API any more.

## Message template for the first batch

This is the manual-steps format from CLAUDE.md. Fill in the repo, and drop the rows this
project doesn't need.

> Claude can't create these: they need your logins, and cloud threads can't reach Stripe or
> Cloudflare. Paste each value in Cloudflare only, never in chat.
>
> 1. In your Stripe sandbox, open [API keys](https://dashboard.stripe.com/apikeys), choose
>    Create restricted key, set Checkout Sessions to Write, and copy it.
> 2. Open [Webhooks](https://dashboard.stripe.com/webhooks) → Add destination, URL
>    `https://<live domain>/api/stripe/webhook`, these events: <WEBHOOK_EVENTS>. Copy the
>    signing secret.
> 3. In Cloudflare open [Workers & Pages](https://dash.cloudflare.com/?to=/:account/workers-and-pages)
>    → `<worker>` → Settings → Variables and secrets → **Production** → Add, type Secret:
>    - `STRIPE_SECRET_KEY`: the key from step 1
>    - `STRIPE_WEBHOOK_SECRET`: the secret from step 2
>    - …
> 4. Same page, **Previews Base**: `STRIPE_SECRET_KEY` with the same sandbox key, and
>    `BETTER_AUTH_SECRET` with any long random string.
> 5. Reply "keys done". Runtime secrets apply without a redeploy; Claude checks the live site.
